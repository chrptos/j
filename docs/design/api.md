## 1. 商品検索

### リクエスト

`GET /products`

| パラメータ | 内容 | 初期案 |
| --- | --- | --- |
| keyword | 商品名の部分一致 | 任意。未指定なら条件なし |
| categoryId | カテゴリID | 任意 |
| minPrice | 価格の下限 | 任意。境界を含む |
| maxPrice | 価格の上限 | 任意。境界を含む |
| sort | 並び順 | `id_asc`（標準）、`price_asc`、`price_desc` |
| limit | 取得件数 | 標準20、1〜100 |
| offset | 取得開始位置 | 標準0、0以上の整数 |

- 商品IDは昇順を基本とする。価格が同じ場合も商品IDの昇順で並べる。
- 初期版はOFFSET方式とし、カーソル方式を比較実験で追加する。
- 件数、ID、価格、offsetの型や範囲が不正な場合は400を返す。
- minPriceがmaxPriceを超える場合は400を返す。
- keywordは大文字小文字を区別し、文字正規化を行わず部分一致で検索する。空文字は条件なしとする。
- `%`・`_`・`\`はワイルドカードではなく文字として検索する。
- categoryIdは1〜9,223,372,036,854,775,807、価格は0〜2,147,483,647、offsetは0〜9,223,372,036,854,775,807とする。
- 同じ検索パラメータの複数指定、空の数値・sort、不正なURLエンコード・UTF-8は400を返す。

### レスポンス

- 成功：200。該当商品がない場合も空のitemsを返す。
- カテゴリが存在しない場合は、検索結果を空にする。
- 次ページの有無を返す。
- hasNextは指定件数より1件多く取得して判定する。

```json
{
  "items": [
    {"id": 1, "name": "商品A", "price": 1000, "categoryName": "カテゴリA"}
  ],
  "limit": 20,
  "offset": 0,
  "hasNext": false
}
```

## 2. 在庫減算

### リクエスト

`POST /products/{productId}/stock/decrements`

```json
{"quantity": 1}
```

- 1リクエストで1商品を指定する。
- productIdとquantityは正の整数とする。
- quantityの最大値と数値の保存型はDB設計で決める。
- 各リクエストを独立した減算として扱う。

### レスポンス

| 状況 | ステータス | コード |
| --- | --- | --- |
| 減算成功 | 200 | — |
| 入力不正 | 400 | INVALID_ARGUMENT |
| 商品なし | 404 | PRODUCT_NOT_FOUND |
| 在庫不足 | 409 | INSUFFICIENT_STOCK |
| 一時的なDB障害 | 503 | [共通エラー設計](errors.md)の分類に従う |
| 予期しない障害 | 500 | INTERNAL_ERROR |

```json
{"productId": 1, "remainingStock": 9}
```

- remainingStockは、このリクエストの更新時点の在庫数を返す。別のリクエストでその後に変わる可能性がある。
- 応答が届かなくても減算が成立している場合がある。再送すると別の減算になるため、負荷試験では自動再試行を行わない。
- 障害試験の整合性確認では、応答成功件数だけでなくDBの更新結果を確認する。確認方法は試験設計で決める。
