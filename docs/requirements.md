# 性能学習基盤 要件定義書

## 1. 商品検索

### ルール

- 商品は識別子・商品名・価格を持ち、1商品につき1カテゴリに属する。
- カテゴリは識別子・カテゴリ名を持つ。
- キーワードは商品名の部分一致で検索する。
- 並び順は商品ID順または価格順とし、同じ価格では商品ID順にする。
- 1ページの件数は標準20件、最大100件とする。
- 同じ条件と同じデータでは、検索結果を一定の順序で返す。

### 機能

- 商品名のキーワード・カテゴリ・価格帯で検索できる。
- 検索結果をページ単位で取得できる。
- 検索結果に商品ID・商品名・価格・カテゴリ名を表示する。

## 2. 在庫減算

### ルール

- 在庫を商品ごとに個数で管理する。
- 減算数量は正の整数とする。
- 在庫数を0以上に保つ。
- 在庫不足の場合は減算要求を拒否する。
- 試験後の在庫数は「試験開始時の在庫数−成功した減算数量の累計」と一致する。

### 機能

- 商品・数量を指定して在庫を減らせる。

## 3. 試験データ

### ルール

- データの生成条件を記録し、同じ条件で再作成できるようにする。
- 試験開始時のデータと在庫数を記録する。

### 機能

- 商品件数と在庫数を指定してデータを生成できる。
- カテゴリや在庫の分布、アクセスの集中度を変えて試験できる。

## 4. 負荷・障害の検証

### ルール

- 成功・業務上の拒否・システム障害を分けて集計する。
- 改善前後は同じデータ・資源・負荷条件で比較する。
- 負荷生成側の限界を確認する。
- 性能試験と障害試験の後に、在庫数と成立した減算数量の整合性を検証する。

### 機能

- 通常負荷・急増・限界探索・長時間運転の試験を実行できる。
- 分散した減算と、一商品へ集中する減算を試験できる。
- API停止・DB遅延・接続枯渇を試験できる。
- 応答時間のp95・p99、成功件数、障害率、処理件数、復旧時間を記録できる。
- CPU・メモリ・GC・DB実行時間・ロック待ち・接続待ちを観測できる。
- コードの版・構成・費用・仮説・測定結果を記録できる。
