# EC 要件定義書

## 1. 商品

### ルール
- 単一事業者の商品を扱う。

### 機能
- 運営者は商品名・説明・カテゴリ・価格・公開状態を登録、変更できる。
- 閲覧者と購入者は、公開商品をキーワード・カテゴリ・価格帯で検索できる。
- 検索結果を一定の並び順でページ単位に取得できる。
- 閲覧者と購入者は、公開商品の情報・現在価格・在庫状況を確認できる。

## 2. 在庫

販売可能在庫は、新しい注文に割り当てられる数量を指す。

### ルール
- 入庫数量は正の整数とする。
- 在庫拠点は1か所とし、商品は個数で管理する。
- 在庫数を0以上に保つ。
- 在庫数は「初期在庫＋入庫累計−確定した注文数量の累計＋キャンセル返却累計」と一致する。

### 機能
- 運営者は在庫に数量を追加できる。

## 3. 注文

### ルール
- 注文数量は正の整数とする。
- 注文時に商品の公開状態、価格、数量、在庫を確認する。
- 全商品が購入可能な場合に注文を確定する。非公開・存在しない商品、在庫不足を含む場合は注文全体を拒否する。
- 注文保存と全商品の在庫減算がまとめて成立した時点で、注文を確定する。
- 注文の状態は「確定」「出荷準備中」「発送済み」「キャンセル済み」とする。
- 「確定」から「出荷準備中」または「キャンセル済み」へ、「出荷準備中」から「発送済み」へ遷移する。
- キャンセルは「確定」状態でのみ受け付ける。
- キャンセルと出荷準備開始が同時に行われた場合は、どちらか一方だけ成立させる。
- 注文金額はサーバーで計算する。
- 注文時の商品名・単価・数量・金額を保持する。
- 同じ注文要求は、購入者と冪等キーで識別する。冪等キーは、再送が同じ購入操作かを判別する識別子を指す。
- 同じ注文要求から作成する注文と在庫減算は一度だけとする。
- 同じ冪等キーで内容が異なる要求は拒否する。
- キャンセル時に、注文全体を取り消して購入数量を在庫に戻す。在庫返却は再送を含め注文ごとに一度だけ行う。

### 機能
- 認証済み購入者は、複数の商品と数量を指定して注文できる。
- 確定済みの注文要求を再送した場合は、元の注文を返す。
- 購入者は自分の注文一覧・詳細・状態を確認できる。
- 注文履歴に、注文時の商品名・単価・数量・合計を表示する。
- 購入者は自分の確定済み注文を全体キャンセルできる。

## 4. 出荷

### ルール

- 出荷準備開始と発送完了は運営者が行う。
- 確定状態の注文を出荷準備中に変更する。
- 出荷準備中の注文を発送済みに変更する。
- 販売可能在庫は注文確定時に減算し、出荷時はその数量を維持する。

### 機能

- 運営者は注文の出荷準備を開始できる。
- 運営者は注文の発送完了を記録できる。

## 5. 通知

### ルール
- 通知には模擬送信先を使う。
- 確定注文の通知予定を保持する。
- 通知に失敗しても、注文の確定状態と在庫減算の結果を維持する。

### 機能
- 注文確定を非同期で通知する。
- 失敗した通知を再試行できる。

## 6. 利用者・権限

### ルール
- 閲覧者は、公開商品の検索・詳細閲覧ができる。
- 購入者は、自分の注文の作成・履歴確認・キャンセルができる。
- 運営者は、商品管理・在庫入庫・出荷準備開始・発送完了の記録ができる。
- 注文の参照・キャンセルは所有者に、商品管理・入庫・出荷操作は運営者に限定する。

### 機能
- 購入者を識別し、操作権限を確認する。
